## 1. О продукте

Дашборд показывает здоровье портфеля ИТ-проектов: светофор по проектам, прогресс целей,
план/факт бюджета, просрочки и причины проблем. Данные загружаются из Excel и
структурируются через DeepSeek; по текущему срезу можно задавать вопросы AI-ассистенту.

**Проблема:** руководителю приходится вручную собирать статусы из таблиц и созвонов,
а проблемы всплывают слишком поздно.

**Цель:** за 1–2 минуты показать, где портфель «горит», почему и что делать дальше.

## 2. Принципы развития

1. **Сначала достоверность данных** — красивый дашборд бесполезен, если цифрам не доверяют.
2. **Один экран — один ответ** — пользователь должен понимать состояние портфеля без чтения инструкции.
3. **AI помогает, но не заменяет** — любой вывод AI должен опираться на данные и быть проверяемым.
4. **Сначала простое решение** — статичный фронтенд и localStorage, backend только там, где без него не обойтись.
5. **Каждая задача — маленький проверяемый инкремент** с понятными критериями приёмки.

## 15. Definition of Ready

Задача готова к работе, если:

- [ ] есть User Story в формате «Я как …, хочу …, чтобы …»;
- [ ] описана ценность и понятно, зачем это пользователю;
- [ ] есть измеримые критерии приёмки;
- [ ] определены границы: что входит и что не входит;
- [ ] для UI есть макет, набросок или ссылка на пример;
- [ ] для данных есть пример `payload.json` или схема;
- [ ] указаны зависимости и риски;
- [ ] задача оценена и имеет приоритет.

## 16. Definition of Done

Задача завершена, если:

- [ ] критерии приёмки выполнены;
- [ ] код работает без ошибок в консоли;
- [ ] проверены светлая и тёмная темы, десктоп и мобильный вид (если применимо);
- [ ] обновлены `TASK.md`, `ROADMAP.md` и `CHANGELOG.md`;
- [ ] добавлены или обновлены тесты (если есть тестовая инфраструктура);
- [ ] промпт и примеры данных актуальны;
- [ ] результат проверен вторым человеком или самопроверкой по чек-листу.

## 17. Как работать с задачами

1. **Идея** появляется в разделе «Бэклог идей» этого файла.
2. Когда идея попадает в релиз, создаётся папка:

   ```text
   docs/tasks/task-NNN-kratkoe-imya/
   ├── TASK.md       # User Story, критерии, границы, риски
   ├── prompt.md     # готовый промпт для ИИ
   ├── mockups/      # скриншоты, схемы, наброски (если есть UI)
   └── payload.json  # пример данных (если задача про данные/API)
   ```

3. В `TASK.md` ставится статус `📋`, затем `🚧`, после проверки — `✅`.
4. После завершения запись переносится в `CHANGELOG.md`.
5. Ссылка на папку задачи добавляется в таблицу релизов и в соответствующий User Story.
