# TASK-003 — Сохранение данных и история загрузок

| Поле | Значение |
|---|---|
| **Статус** | 📋 Запланировано |
| **Приоритет** | `P0` |
| **Релиз** | 0.2.0 — «Данные, которым можно доверять» |
| **Эпик** | Данные и импорт |
| **Оценка** | 3–5 дней |
| **Зависимости** | Нет. Желательно после [task-009](../task-009-excel-validation/TASK.md) |

## User Story

> Я как аналитик, хочу, чтобы загруженные данные, фильтры и настройки сохранялись после
> перезагрузки страницы, чтобы не загружать Excel заново при каждом открытии дашборда.
>
> Я как администратор, хочу видеть историю импортов и возвращаться к предыдущей версии,
> чтобы исправить неудачную загрузку без повторной подготовки файла.

## Зачем это нужно

Сейчас `rawProjects` живёт только в памяти. Любая перезагрузка возвращает демо-данные,
а результат импорта Excel пропадает. Это главный барьер для реального использования
дашборда: пользователь не может закрыть вкладку, не потеряв работу.

## Область работ

### Входит

- Сохранение состояния в `localStorage` (или IndexedDB при больших объёмах).
- Восстановление состояния при старте: проекты, фильтры, правила светофора.
- Версионирование схемы и миграции при изменении формата.
- Автосохранение с задержкой (debounce) после изменений.
- Кнопка «Сбросить к демо-данным» с подтверждением.
- Экспорт состояния в JSON и импорт JSON обратно.
- История последних 10 импортов: дата, имя файла, количество проектов, снимок данных.
- Откат к выбранной версии с подтверждением.
- Индикатор «Данные сохранены» / «Есть несохранённые изменения».
- Синхронизация между вкладками через событие `storage`.

### Не входит

- Серверное хранение и совместная работа.
- Синхронизация между устройствами.
- Полноценная система версий с diff и ветками.
- Шифрование данных (отдельная задача по безопасности).

## Модель состояния

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-10-30T12:00:00.000Z",
  "source": {
    "type": "excel",
    "fileName": "portfolio_2026_10.xlsx",
    "importedAt": "2026-10-30T11:55:00.000Z"
  },
  "filters": {
    "direction": "all",
    "project": "all"
  },
  "healthRules": {
    "overdueMonthsRed": 1,
    "budgetOverrunPercentRed": 0,
    "monthsToCloseYellow": 3
  },
  "projects": []
}
```

## Сценарии

1. **Первый запуск.** Сохранённого состояния нет — показываются демо-данные,
   в шапке бейдж «Демо-данные».
2. **Импорт Excel.** После применения файла состояние сохраняется, бейдж меняется
   на «Данные от 30.10.2026».
3. **Перезагрузка.** Дашборд восстанавливает проекты, фильтры и правила.
4. **История.** Пользователь открывает «История», видит 10 последних импортов,
   выбирает предыдущий и нажимает «Восстановить».
5. **Сброс.** Пользователь нажимает «Сбросить к демо», подтверждает — состояние
   возвращается к `DEFAULT_PROJECTS`.
6. **Ошибка квоты.** Хранилище переполнено — показывается понятное сообщение
   и предложение выгрузить JSON.

## Критерии приёмки

- [ ] После перезагрузки сохраняются проекты, цели, фильтры и правила.
- [ ] В шапке видно происхождение данных и дату обновления.
- [ ] Есть кнопка сброса к демо-данным с подтверждением.
- [ ] Экспорт JSON создаёт файл, который можно импортировать обратно.
- [ ] История хранит последние 10 импортов.
- [ ] Откат к версии восстанавливает проекты и показывает подтверждение.
- [ ] При переполнении хранилища нет «молчаливой» потери данных.
- [ ] Изменения в одной вкладке отражаются в другой без перезагрузки.
- [ ] `localStorage` не содержит API-ключ в составе общего состояния.

## Технические заметки

- Ключи хранилища:
  - `dashboard_state_v1` — текущее состояние;
  - `dashboard_history_v1` — массив снимков;
  - `deepseek_api_key` — существующий ключ, не дублировать.
- Писать отдельный модуль `storage.js`:
  - `loadState()`, `saveState(state)`, `resetState()`, `exportState()`, `importState(file)`;
  - `pushSnapshot(state, meta)`, `listSnapshots()`, `restoreSnapshot(id)`.
- `saveState` оборачивать в `try/catch` и обрабатывать `QuotaExceededError`.
- Для миграций: `migrate(state)` с проверкой `schemaVersion`.
- Не сохранять вычисляемые поля (`health`, `reasons`, `overdueMonths`) — только исходные данные.
- Debounce 300–500 мс, чтобы не писать на каждый клик.
- Пример состояния — [payload.json](payload.json).

## Риски и открытые вопросы

- `localStorage` ограничен ~5 МБ. Для больших портфелей нужен IndexedDB.
- Пользователь может открыть две вкладки и перезаписать изменения — нужна стратегия
  разрешения конфликтов (последняя запись побеждает или предупреждение).
- Нужно ли хранить историю импортов целиком или только метаданные + diff?
- Что считать «источником истины»: Excel или ручные правки в дашборде?
- Нужно ли автоматически удалять старые снимки по времени?
