## Контекст

Ты работаешь с проектом «Здоровье ИТ-проектов» — статическим дашбордом на чистом
HTML/CSS/JS без сборки и фреймворков. Основные файлы:

- `Дашборд_5.html` — разметка;
- `app.js` — рендер, фильтры, расчёт здоровья, интеграция с DeepSeek и Excel;
- `data.js` — демо-данные;
- `styles.css` — стили, светлая и тёмная темы.

Данные сейчас хранятся в памяти и теряются после перезагрузки. Дашборд локальный,
без backend.

## Задача

Реализовать **демонстрационный слой авторизации и ролей доступа** для дашборда.
Это MVP для командного сценария, а не production-система безопасности.

Роли: `admin`, `leader`, `pm`, `viewer`.

Матрица прав:

| Действие | admin | leader | pm | viewer |
|---|:---:|:---:|:---:|:---:|
| Смотреть весь портфель | да | нет | нет | да |
| Смотреть только своё направление | да | да | да | да |
| Загружать Excel | да | да | нет | нет |
| Редактировать проект/цель | да | да | да | нет |
| Менять правила светофора | да | да | нет | нет |
| Управлять пользователями | да | нет | нет | нет |
| Смотреть журнал действий | да | нет | нет | нет |

## Что нужно сделать

1. **Экран входа** — логин, пароль, кнопка «Войти», понятная ошибка при неверных данных.
2. **Сессия** — хранить текущего пользователя в `sessionStorage`; при перезагрузке
   восстанавливать сессию; кнопка «Выйти».
3. **Роли** — единая функция `can(action, resource)`, через которую проверяются все действия.
4. **Ограничение данных** — `leader` и `pm` видят только назначенные направления;
   фильтры и таблица целей тоже учитывают ограничение.
5. **Скрытие действий** — если действие недоступно, кнопка скрыта или disabled;
   при прямом вызове функции — понятная ошибка «Недостаточно прав».
6. **Админ-панель** — список пользователей, создание, смена роли, назначение направлений.
7. **Журнал действий** — вход, выход, импорт Excel, изменение настроек, смена ролей.
   Хранить последние 100 записей.
8. **Демо-пользователи** — 4 учётные записи по одной на роль, пароли захэшированы
   через Web Crypto API (`crypto.subtle.digest`), не в открытом виде. Учти, что
   `crypto.subtle` работает только в secure context и может быть недоступен при
   открытии через `file://`; предусмотри понятное сообщение и запуск через локальный сервер.
9. **Стили** — экран входа и админ-панель в стиле дашборда: стекло, скругления,
   светлая и тёмная темы, мобильная адаптация.
10. **Документация** — короткий раздел в `README` или комментарий в коде:
    demo-режим не защищает данные без backend.

## Ограничения

- Не добавляй фреймворки, сборщики и npm-зависимости.
- Не ломай текущий функционал: фильтры, таблицу целей, импорт Excel, чат DeepSeek.
- Не храни пароли и API-ключи в открытом виде.
- Не выдавай demo-авторизацию за production-безопасность.
- Код должен быть понятным, с комментариями на русском в ключевых местах.
- Все пользовательские строки экранируй через существующий `escapeHtml`.

## Критерии приёмки

- [ ] Без входа дашборд не показывается.
- [ ] После входа видны имя и роль пользователя.
- [ ] `viewer` не может загрузить Excel и изменить данные.
- [ ] `pm` видит только своё направление.
- [ ] `admin` создаёт пользователя и назначает роль.
- [ ] Журнал действий пополняется.
- [ ] Выход очищает сессию.
- [ ] Светлая и тёмная темы, мобильный вид не сломаны.
