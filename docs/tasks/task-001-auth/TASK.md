## User Story

> Я как администратор портфеля, хочу выдавать пользователям роли «руководитель», «PM»,
> «аналитик» и «гость», чтобы каждый видел только свои направления и не мог случайно
> изменить чужие данные.

## Зачем это нужно

Сейчас дашборд — локальная страница без понятия «пользователь». Любой, кто открыл файл,
видит весь портфель и может загрузить новый Excel. Для командного использования нужны
как минимум разграничение видимости и защита от случайных изменений.

## Область работ

### Входит

- Экран входа: логин, пароль, «запомнить меня».
- Четыре роли: `admin`, `leader`, `pm`, `viewer`.
- Матрица прав: просмотр, импорт, редактирование, настройки, управление пользователями.
- Ограничение видимости направлений для `leader` и `pm`.
- Экран администратора: список пользователей, роль, доступные направления.
- Журнал действий: вход, импорт, изменение настроек, смена ролей.
- Выход из системы и блокировка экрана при истечении сессии.

### Не входит

- Интеграция с корпоративным SSO/LDAP (отдельная задача).
- Полноценная защита от атак, аудит безопасности, соответствие требованиям ИБ.
- Восстановление пароля по email.
- Мобильное приложение.

## Роли и права

| Действие | admin | leader | pm | viewer |
|---|:---:|:---:|:---:|:---:|
| Смотреть весь портфель | ✅ | — | — | ✅ |
| Смотреть своё направление | ✅ | ✅ | ✅ | ✅ |
| Загружать Excel | ✅ | ✅ | — | — |
| Редактировать проект/цель | ✅ | ✅ | ✅ | — |
| Менять правила светофора | ✅ | ✅ | — | — |
| Управлять пользователями | ✅ | — | — | — |
| Смотреть журнал действий | ✅ | — | — | — |

## Сценарии

1. **Вход.** Пользователь открывает дашборд, вводит логин и пароль, попадает на главный экран.
2. **Ограничение видимости.** `pm` направления «А» видит только проекты направления «А»;
   фильтр направлений содержит только доступные значения.
3. **Запрет действия.** `viewer` не видит кнопку загрузки Excel; при попытке вызвать
   действие напрямую получает сообщение «Недостаточно прав».
4. **Управление пользователями.** `admin` создаёт пользователя, назначает роль и направления,
   после чего пользователь может войти.
5. **Журнал.** После импорта Excel в журнале появляется запись: кто, когда, какой файл,
   сколько проектов.

## Критерии приёмки

- [ ] Без входа дашборд недоступен: показывается экран логина.
- [ ] После входа отображается имя пользователя и его роль.
- [ ] Роль ограничивает и видимость данных, и доступные действия.
- [ ] `viewer` не может изменить данные ни через UI, ни через вызов функции в консоли.
- [ ] `admin` может создать пользователя и назначить ему направление.
- [ ] Журнал действий хранит минимум 100 последних записей.
- [ ] Выход очищает сессию и возвращает на экран входа.
- [ ] Пароли не хранятся в открытом виде.
- [ ] В README/`TASK.md` явно указано, что demo-режим без backend не является продакшн-защитой.

## Технические заметки

- Сейчас проект — статический фронтенд: `Дашборд_5.html`, `app.js`, `data.js`, `styles.css`.
- Для реальной авторизации нужен backend или BaaS. Без него можно сделать только
  демонстрационный слой в `localStorage`, который **не является защитой**.
- Предлагаемая структура:
  - `auth.js` — вход, выход, текущий пользователь, проверка прав;
  - `users.js` — демо-пользователи и роли;
  - `audit.js` — запись действий;
  - `login.html` или модальное окно входа.
- Пароли в demo-режиме хешировать через Web Crypto API (`crypto.subtle.digest`), не хранить открытый текст.
  Учесть, что `crypto.subtle` доступен только в secure context: при открытии через `file://`
  он может быть недоступен. Предусмотреть понятное сообщение и рекомендовать локальный сервер.
- Проверка прав должна быть в одной функции `can(action, resource)`, а не размазана по коду.
- Сессия: `sessionStorage` для demo, HTTP-only cookie для backend-версии.

## Риски и открытые вопросы

- **Главный риск:** сделать «авторизацию» на фронтенде и создать ложное чувство безопасности.
  До появления backend задачу нельзя считать production-ready.
- Нужно ли ограничивать видимость по направлениям или по конкретным проектам?
- Должен ли `leader` видеть бюджеты своих проектов?
- Где хранить журнал: localStorage, backend или внешний сервис?
- Нужна ли интеграция с корпоративным SSO? Если да — оценка и архитектура меняются.
