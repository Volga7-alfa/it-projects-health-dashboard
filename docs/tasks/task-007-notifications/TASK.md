## User Story

> Я как руководитель, хочу получать краткий дайджест по понедельникам, чтобы быть
> в курсе изменений без открытия дашборда.
>
> Я как руководитель, хочу получать уведомление, когда проект становится красным,
> чтобы реагировать сразу, а не на следующей планёрке.

## Зачем это нужно

Дашборд помогает, только когда его открывают. Если руководитель не заглянул в понедельник,
критический проект может остаться незамеченным. Уведомления превращают дашборд
из «пассивной таблицы» в инструмент контроля.

## Область работ

### Входит

- Генерация текста дайджеста по текущему срезу:
  - новые красные проекты;
  - проекты с просрочкой;
  - перерасход бюджета;
  - цели, просроченные за неделю.
- Кнопка «Скопировать дайджест».
- Кнопка «Отправить на email» через `mailto:` с готовой темой и текстом.
- Настройка получателей и времени дайджеста (локально).
- История отправленных дайджестов (локально).
- Алерт при переходе проекта в красный статус:
  - сравнение с предыдущим сохранённым состоянием;
  - уведомление только при новом переходе;
  - защита от повторного алерта без изменений.
- Шаблоны сообщений на русском.
- Ссылка на дашборд в каждом сообщении.

### Не входит

- Собственный сервер рассылки.
- Гарантированная доставка и повторные попытки.
- Push-уведомления в браузере (можно добавить позже).
- Рассылка по SMS.
- Хранение токенов Telegram/Email на фронтенде.

## Каналы

| Канал | MVP | Продакшн |
|---|---|---|
| Буфер обмена | ✅ | ✅ |
| `mailto:` | ✅ | ✅ |
| Telegram | — | Через backend/webhook |
| Email-сервер | — | Через backend |
| Webhook (Slack/Teams) | — | Через backend |

> Важно: токен Telegram-бота нельзя хранить в статическом фронтенде. Для реальной
> отправки нужен backend или serverless-функция.

## Сценарии

1. **Дайджест вручную.** Пользователь нажимает «Сформировать дайджест», получает текст,
   копирует и отправляет в чат.
2. **Письмо.** Пользователь нажимает «Отправить на email», открывается почтовый клиент
   с заполненной темой и телом.
3. **Новый красный проект.** После импорта Excel проект А4 стал красным.
   Система показывает алерт «А4 перешёл в красный: перерасход 0,2 млн».
4. **Повторный импорт.** А4 остаётся красным — повторного алерта нет.
5. **Возврат в зелёный и снова красный.** Алерт появляется снова, потому что переход новый.
6. **Настройка.** Пользователь выбирает день недели и время, получателей — настройки
   сохраняются.

## Критерии приёмки

- [ ] Дайджест формируется по кнопке и содержит ключевые риски.
- [ ] Дайджест можно скопировать.
- [ ] `mailto:` открывает почтовый клиент с темой и телом.
- [ ] Алерт появляется только при новом переходе в красный.
- [ ] Повторный алерт без изменений не отправляется.
- [ ] В сообщении есть проект, причина и ссылка на дашборд.
- [ ] Настройки получателей и времени сохраняются.
- [ ] История отправок доступна.
- [ ] Токены и пароли не хранятся на фронтенде.
- [ ] Тексты понятны и не содержат технического мусора.

## Технические заметки

- Сравнение состояний: хранить `lastKnownHealth` по каждому проекту
  (`localStorage`, ключ `dashboard_health_snapshot_v1`).
- Алгоритм:
  1. посчитать текущий health;
  2. сравнить с прошлым;
  3. выбрать проекты, где `previous !== 'red' && current === 'red'`;
  4. сформировать сообщения;
  5. сохранить новый снимок.
- Шаблон сообщения:
  ```text
  🔴 А4 — перерасход 0,2 млн ₽
  Направление: А
  План: 1,0 млн ₽ · Факт: 1,2 млн ₽
  Подробнее: <ссылка на дашборд с фильтром>
  ```
- Для `mailto:` использовать `encodeURIComponent`.
- Для реальной отправки — абстракция `notify(channel, payload)` с реализациями
  `clipboard`, `mailto`, `webhook`.
- Пример payload — [payload.json](payload.json).
- Расписание в статическом приложении можно эмулировать при открытии:
  «если сегодня понедельник и дайджест ещё не отправлен — показать напоминание».
  Настоящее расписание требует cron/backend.

## Риски и открытые вопросы

- Слишком много алертов → пользователь перестанет их читать. Нужен порог и группировка.
- Без backend нельзя гарантировать отправку по расписанию.
- Нужно ли отправлять алерты в общий чат команды или только руководителю?
- Кто настраивает получателей?
- Можно ли включать в сообщение суммы бюджетов — это чувствительные данные?
- Нужна ли тихая отправка или подтверждение перед каждым сообщением?
