# Промпт для ИИ — TASK-007 «Уведомления о рисках и еженедельный дайджест»

> Приложи `app.js`, `data.js`, `Дашборд_5.html`, `styles.css` и `payload.json`.

---

## Контекст

Дашборд «Здоровье ИТ-проектов» — статическое приложение на чистом HTML/CSS/JS.
Функция `getProjectHealth(project)` возвращает `{ status, label }`, где `status` —
`red`, `yellow`, `green` или `closed`. `buildReasons(project)` возвращает массив причин.
Данные проектов — `rawProjects`.

## Задача

Добавить генерацию дайджеста и алерты о новых красных проектах.

## Требования

### 1. Дайджест

- Кнопка «Сформировать дайджест».
- Текст содержит:
  - дату;
  - количество проектов в срезе;
  - новые красные проекты;
  - проекты с просрочкой;
  - перерасход;
  - просроченные цели;
  - ссылку на дашборд.
- Кнопки «Скопировать» и «Отправить на email» (`mailto:`).
- Если рисков нет — текст «Критических рисков не обнаружено».

### 2. Алерты о новых красных

- Хранить снимок здоровья: `{ project: { status, updatedAt } }`
  в `localStorage` под ключом `dashboard_health_snapshot_v1`.
- При пересчёте данных:
  - сравнить текущий статус с прошлым;
  - показать алерт только для перехода `не red → red`;
  - не показывать повторно, если статус не менялся;
  - если проект вернулся в зелёный и снова стал красным — показать снова.
- Алерт: проект, направление, причина, ссылка на карточку/фильтр.
- Сохранять новый снимок после обработки.

### 3. Настройки

- Получатели (email/имя), день недели, время.
- Хранить локально.
- Кнопка «Проверить сейчас» — сформировать дайджест немедленно.
- Напоминание при открытии, если сегодня выбранный день и дайджест ещё не сформирован.

### 4. Каналы

- MVP: буфер обмена и `mailto:`.
- Абстракция `notify(channel, payload)`, чтобы позже добавить Telegram/webhook.
- Не хранить токены ботов и SMTP-пароли во фронтенде.
- В интерфейсе честно указать: «Для отправки в Telegram нужен backend».

## Ограничения

- Без фреймворков и сборки.
- Не ломать существующие карточки, фильтры, импорт и чат.
- Все пользовательские строки экранировать.
- Не отправлять данные автоматически без действия пользователя в MVP.
- Стили — в духе дашборда, светлая и тёмная темы.

## Критерии приёмки

- [ ] Дайджест формируется и содержит риски.
- [ ] Копирование работает.
- [ ] `mailto:` открывает клиент с темой и телом.
- [ ] Алерт только при новом переходе в красный.
- [ ] Повторного алерта без изменений нет.
- [ ] В сообщении есть проект, причина и ссылка.
- [ ] Настройки сохраняются.
- [ ] История отправок доступна.
- [ ] В UI нет токенов и паролей.
- [ ] Тексты понятные.

## Формат ответа

1. Список изменённых файлов.
2. Новый модуль `notifications.js` с полным кодом.
3. Патчи для `app.js`, HTML и CSS.
4. Примеры сообщений.
5. Чек-лист проверки, включая сценарий «красный → зелёный → красный».
6. Что потребуется для реальной отправки в Telegram/Email.
