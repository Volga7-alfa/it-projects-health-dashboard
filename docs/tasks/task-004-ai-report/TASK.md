## User Story

> Я как руководитель направления, хочу одной кнопкой получать статус-отчёт по портфелю,
> чтобы не собирать его вручную перед планёркой.
>
> Я как PM, хочу задавать вопросы по данным и видеть, на какие проекты и цели опирается
> ответ, чтобы быстро проверять выводы AI.

## Зачем это нужно

Сейчас DeepSeek-чат отвечает на свободные вопросы, но не готовит регулярный отчёт
и не показывает, откуда взяты выводы. Руководителю нужен предсказуемый результат
в одинаковом формате: сводка, проблемные проекты, причины, рекомендации, следующие шаги.

## Область работ

### Входит

- Кнопка «Сформировать отчёт» в шапке или модальном окне.
- Отчёт по текущему срезу с учётом выбранных фильтров.
- Структура отчёта:
  1. **Сводка** — 2–3 предложения о состоянии портфеля.
  2. **Красная зона** — проекты «Проблема» с причинами.
  3. **Жёлтая зона** — проекты «Внимание» и что может ухудшиться.
  4. **Рекомендации** — 2–3 конкретных действия по каждой проблемной зоне.
  5. **Следующие шаги** — что проверить или запросить у команд.
- Указание источников: дата отчёта, количество проектов, список использованных проектов.
- Кнопки «Скопировать», «Скачать .md», «Повторить».
- История последних 5 отчётов (локально).
- Индикатор загрузки, отмена запроса, понятные ошибки.
- Ограничение объёма данных, чтобы не превышать контекст модели.

### Не входит

- Автономные действия AI (изменение данных, отправка писем).
- Стриминг ответа (можно добавить позже).
- Обучение на данных компании.
- Гарантия фактической корректности рекомендаций — AI только помощник.
- Замена ручного анализа.

## Шаблон отчёта

```markdown
# Статус-отчёт по портфелю ИТ-проектов
Дата: 30.10.2026
Проектов в срезе: 8
Источник данных: Excel, portfolio_2026_10.xlsx

## Сводка
…

## Красная зона
### А4 — перерасход 0,2 млн
- Причина: …
- Что делать: …

## Жёлтая зона
…

## Рекомендации
1. …
2. …

## Следующие шаги
- [ ] …
```

## Сценарии

1. **Генерация.** Пользователь нажимает «Сформировать отчёт», видит spinner,
   через несколько секунд — структурированный отчёт.
2. **Фильтр.** Пользователь выбирает направление «А» и формирует отчёт только по нему.
3. **Источники.** В отчёте указано, какие проекты использованы; по клику можно
   перейти к карточке проекта.
4. **Ошибка ключа.** Если ключ не задан, показывается сообщение и кнопка «Открыть настройки».
5. **Ошибка API.** Показывается человеческий текст, отчёт не теряется.
6. **Копирование.** Пользователь копирует отчёт в буфер и вставляет в письмо.

## Критерии приёмки

- [ ] Отчёт генерируется по кнопке и соответствует структуре.
- [ ] Учитываются активные фильтры.
- [ ] В отчёте есть дата, количество проектов и список источников.
- [ ] Рекомендации привязаны к конкретным проектам и причинам.
- [ ] Ответ AI не вставляется в DOM как небезопасный HTML.
- [ ] Есть состояния загрузки, ошибки и пустого результата.
- [ ] Отчёт можно скопировать и скачать в `.md`.
- [ ] История последних 5 отчётов сохраняется локально.
- [ ] При отсутствии ключа пользователь понимает, что делать.
- [ ] Токен-лимит: данные обрезаются предсказуемо, без «молчаливого» пропуска проектов.

## Технические заметки

- Использовать существующую `callDeepSeek(messages, { json, temperature })` из `app.js`.
- Для отчёта лучше `response_format: { type: 'json_object' }` и строгая схема:
  `summary`, `redZone[]`, `yellowZone[]`, `recommendations[]`, `nextSteps[]`, `sources[]`.
- Если JSON невалиден — fallback: показать текст как есть, но экранировать.
- Для отображения Markdown использовать безопасный рендер или`textContent` +
  простую разметку. Не подключать тяжёлые библиотеки без необходимости.
- Данные для промпта: компактный JSON без вычисляемых полей; ограничить, например,
  50 проектами и 10 целями на проект, явно указать, что данные обрезаны.
- Не отправлять API-ключ никуда, кроме `api.deepseek.com`.
- Сохранять отчёты в `localStorage` под ключом `dashboard_reports_v1`.
- Пример запроса и ответа — [payload.json](payload.json).

## Риски и открытые вопросы

- AI может «придумать» причину, которой нет в данных. Нужно требовать ссылку на поле.
- Стоимость запросов: длинный отчёт по большому портфелю может быть дорогим.
- Нужно ли хранить отчёты на сервере для командного доступа?
- Должен ли отчёт автоматически формироваться по расписанию?
- Как проверять, что рекомендации не противоречат регламентам компании?
