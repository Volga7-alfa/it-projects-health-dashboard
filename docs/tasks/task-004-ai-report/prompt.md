# Промпт для ИИ — TASK-004 «AI-статус-отчёт и рекомендации»

> Приложи `app.js`, `data.js`, `Дашборд_5.html`, `styles.css` и `payload.json`
> из этой папки.

---

## Контекст

Дашборд «Здоровье ИТ-проектов» уже умеет:
- считать статус проекта (`red`, `yellow`, `green`, `closed`);
- показывать причины проблем (просрочка, перерасход, просроченные цели);
- отправлять запросы в DeepSeek через `callDeepSeek(messages, options)`
  и вести чат по текущим данным.

Данные проектов — массив `rawProjects` в формате:

```js
{
  direction, leader, project, status, openDate, planClose, factClose,
  planBudget, factBudget,
  goals: [{ name, planDate, status }]
}
```

## Задача

Добавить генерацию структурированного статус-отчёта по текущему срезу данных.

## Требования

### 1. Кнопка и сценарий

- Кнопка «Сформировать отчёт» в шапке или в модальном окне настроек.
- Учитывать активные фильтры «Направление» и «Проект».
- Показывать spinner и блокировать повторный запуск.
- При ошибке — понятное сообщение и кнопка «Повторить».

### 2. Формат отчёта

Запросить у DeepSeek JSON:

```json
{
  "summary": "2–3 предложения",
  "redZone": [
    {
      "project": "А4",
      "direction": "А",
      "reason": "перерасход 0,2 млн",
      "recommendation": "Проверить договор и согласовать допбюджет"
    }
  ],
  "yellowZone": [
    { "project": "А2", "reason": "до закрытия меньше 3 месяцев, нет выполненных целей" }
  ],
  "recommendations": ["…"],
  "nextSteps": ["…"],
  "sources": ["А1", "А2", "А4"]
}
```

### 3. Отображение

- Заголовок, дата, количество проектов, источник данных.
- Секции: «Сводка», «Красная зона», «Жёлтая зона», «Рекомендации», «Следующие шаги».
- Список источников — ссылки/кнопки, которые фильтруют дашборд по проекту.
- Кнопки «Скопировать», «Скачать .md», «Сформировать заново».

### 4. Безопасность

- Не вставлять ответ AI через `innerHTML` без экранирования.
- Если JSON невалиден — показать сырой текст в `textContent` с пометкой.
- Не отправлять ключ никуда, кроме `api.deepseek.com`.

### 5. Ограничения контекста

- Перед отправкой сжать данные: только нужные поля, максимум 50 проектов,
  до 10 целей на проект.
- Если данные обрезаны — явно написать это в промпте и в отчёте.
- Ограничить `temperature` значением 0.2–0.3.

### 6. История

- Хранить последние 5 отчётов в `localStorage` (`dashboard_reports_v1`).
- Показывать дату, срез (фильтры), возможность открыть или удалить.

## Ограничения

- Без фреймворков и сборки.
- Не ломать существующий чат и импорт Excel.
- Не делать автоматических изменений данных по результатам отчёта.
- Не добавлять тяжёлые Markdown-библиотеки без необходимости.
- Интерфейс — на русском, в стиле дашборда.

- [ ] Структура отчёта соответствует схеме.
