# TASK-009 — Предпросмотр и валидация импорта Excel

| Поле | Значение |
|---|---|
| **Статус** | 📋 Запланировано |
| **Приоритет** | `P0` |
| **Релиз** | 0.2.0 — «Данные, которым можно доверять» |
| **Эпик** | Данные и импорт |
| **Оценка** | 4–6 дней |
| **Зависимости** | SheetJS уже подключён; желательно до [task-003](../task-003-persistence/TASK.md) |

## User Story

> Я как руководитель портфеля, хочу видеть, как распознан файл, до применения данных,
> чтобы не испортить дашборд ошибкой импорта.
>
> Я как аналитик, хочу получать ошибки с номером строки и названием колонки, чтобы
> быстро исправлять Excel, а не гадать, что пошло не так.

## Зачем это нужно

Сейчас файл сразу отправляется в DeepSeek, а результат без проверки заменяет данные
дашборда. Если модель ошиблась в дате, статусе или пропустила проект, пользователь
узнает об этом только по странным цифрам. Нет ни предпросмотра, ни построчных ошибок,
ни возможности отменить импорт.

## Область работ

### Входит

- Чтение Excel на клиенте через SheetJS (уже есть).
- Выбор листа, если в книге несколько листов.
- Определение строки заголовков и обязательных колонок.
- Детерминированный парсинг типовых таблиц **до** обращения к AI.
- AI-структурирование только для неоднозначных случаев (опционально).
- Модальное окно предпросмотра:
  - сколько проектов и целей распознано;
  - таблица «проект — направление — цели — бюджет»;
  - список ошибок и предупреждений;
  - кнопки «Применить», «Отмена», «Скачать ошибки».
- Валидация:
  - обязательные поля: проект, направление, статус;
  - даты в формате `YYYY-MM-DD` или Excel-дата;
  - бюджеты — неотрицательные числа;
  - статус проекта: `открыт` / `закрыт`;
  - статус цели: `выполнено` / `в работе` / `просрочено` / `не выполнено`;
  - цели без названия;
  - строки-продолжения без проекта;
  - дубли проектов и целей;
  - дата закрытия раньше даты открытия.
- Ошибки с номером строки, колонкой, ожидаемым форматом и примером.
- Импорт применяется только после подтверждения.
- Если ошибок критично много — блокировать применение.
- Сохранение исходного файла и результата в историю (после task-003).

### Не входит

- Поддержка формул Excel и сводных таблиц.
- Импорт из Google Sheets.
- Полноценный конструктор колонок с drag-and-drop.
- Ручное сопоставление каждой колонки (можно добавить позже).
- Загрузка нескольких файлов одновременно.

## Сценарии

1. **Успешный импорт.** Пользователь выбирает файл, видит «Распознано 8 проектов,
   21 цель, ошибок нет», нажимает «Применить» — дашборд обновляется.
2. **Ошибка в дате.** В строке 7 дата `31.02.2026`. Предпросмотр показывает ошибку
   «Строка 7, колонка "План закрытия": некорректная дата. Ожидается ГГГГ-ММ-ДД».
   Кнопка «Применить» заблокирована или требует подтверждения.
3. **Нет обязательного поля.** В строке 10 пустое название проекта. Ошибка:
   «Строка 10: не указан проект».
4. **Строка-продолжение.** Строка без проекта содержит цель — она добавляется
   к предыдущему проекту, в предпросмотре это видно.
5. **Отмена.** Пользователь нажимает «Отмена» — данные дашборда не меняются.
6. **Скачать ошибки.** Пользователь выгружает список ошибок в CSV/Excel и исправляет файл.

## Критерии приёмки

- [ ] Перед применением всегда показывается предпросмотр.
- [ ] Видно количество распознанных проектов и целей.
- [ ] Ошибки содержат строку, колонку, ожидаемый формат и пример.
- [ ] Кнопка «Применить» не меняет данные, пока пользователь не подтвердил.
- [ ] «Отмена» полностью сохраняет прежние данные.
- [ ] Строки-продолжения корректно присоединяются к предыдущему проекту.
- [ ] Дубли целей обнаруживаются и показываются.
- [ ] Некорректные даты и бюджеты не проходят молча.
- [ ] Можно скачать список ошибок.
- [ ] После применения обновляются карточки, фильтры и таблица целей.
- [ ] Большой файл (до 1000 строк) не вешает интерфейс.
- [ ] Работает в светлой и тёмной темах, на мобильном.

## Технические заметки

- Использовать существующие `readExcelRows(file)` и `rowsToPromptText(rows)`.
- Разделить поток:
  1. `readExcelRows` → сырые строки;
  2. `parseRows(rows)` → `{ projects, errors, warnings }` (детерминированно);
  3. если структура не распознана — `convertExcelViaDeepSeek(rows)`;
  4. `validateProjects(projects)` → ошибки;
  5. предпросмотр;
  6. `applyImport(result)` → обновление `rawProjects`.
- Не отправлять в AI данные, которые можно разобрать детерминированно.
- Для дат: `XLSX.SSF.parse_date_code` или `cellDates: true` + проверка `instanceof Date`.
- Для больших файлов — ограничить предпросмотр первыми 100 строками, но валидировать все.
- Ошибки хранить в структуре:
  ```js
  { row: 7, column: 'План закрытия', code: 'INVALID_DATE', message: '…', example: '2026-12-31' }
  ```
- Не вставлять имена файлов и ячейки в DOM без экранирования.
- Пример данных и ошибок — [payload.json](payload.json).
- Макет — [mockups/import-preview.md](mockups/import-preview.md).

## Риски и открытые вопросы

- AI может «исправить» данные, которых нет, — предпросмотр обязателен.
- Разные компании присылают разные форматы; нужен ли настраиваемый маппинг колонок?
- Объединённые ячейки и несколько строк на проект усложняют парсинг.
- Что делать с предупреждениями: блокировать импорт или разрешать?
- Нужно ли сохранять исходный Excel для аудита?
- Сколько ошибок показывать: все или первые 50?
