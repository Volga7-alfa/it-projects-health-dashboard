# Промпт для ИИ — TASK-009 «Предпросмотр и валидация импорта Excel»

> Приложи `app.js`, `data.js`, `Дашборд_5.html`, `styles.css` и `payload.json`.

---

## Контекст

Сейчас импорт Excel работает так:

1. `readExcelRows(file)` читает первый лист через SheetJS;
2. `rowsToPromptText(rows)` превращает строки в текст;
3. `convertExcelViaDeepSeek(rows)` просит DeepSeek вернуть JSON;
4. результат сразу заменяет `rawProjects` и перерисовывает дашборд.

Проблема: нет предпросмотра, нет построчной валидации, ошибка модели сразу попадает
в данные. Нужно вставить этап проверки и подтверждения.

## Задача

Добавить предпросмотр импорта и валидацию Excel до применения данных.

## Требования

### 1. Разбор файла

- Оставить чтение через SheetJS.
- Если в книге несколько листов — дать выбрать лист.
- Определить строку заголовков.
- Сначала попробовать детерминированный парсинг типовой таблицы.
- AI использовать только если структура не распознана или неоднозначна.
- Не отправлять в AI то, что можно разобрать кодом.

### 2. Нормализация

Привести к текущей модели:

```js
{
  direction, leader, project, status, openDate, planClose, factClose,
  planBudget, factBudget,
  goals: [{ name, planDate, status }]
}
```

Правила:

- строки без проекта — продолжение целей предыдущего проекта;
- даты — `YYYY-MM-DD` или `null`;
- бюджеты — неотрицательные числа;
- статус проекта — `открыт` / `закрыт`;
- статус цели — `выполнено` / `в работе` / `просрочено` / `не выполнено`;
- пустые значения — `null` для дат, `0` для чисел.

### 3. Валидация

Проверить:

- обязательные поля: проект, направление, статус;
- корректность дат;
- дата закрытия не раньше даты открытия;
- неотрицательные бюджеты;
- допустимые статусы;
- цели без названия;
- дубли проектов;
- дубли целей внутри проекта;
- строки-продолжения без предыдущего проекта.

Формат ошибки:

```js
{
  row: 7,
  column: "План закрытия",
  code: "INVALID_DATE",
  message: "Некорректная дата",
  example: "2026-12-31"
}
```

### 4. Предпросмотр

Модальное окно:

- заголовок «Проверка импорта»;
- файл и лист;
- сводка: проектов, целей, ошибок, предупреждений;
- таблица проектов: направление, проект, цели, план/факт бюджета;
- блок ошибок: строка, колонка, сообщение, пример;
- блок предупреждений;
- кнопки «Применить», «Отмена», «Скачать ошибки».
- Если есть критические ошибки — «Применить» disabled или требует явного подтверждения.
- Предпросмотр не должен менять `rawProjects`.

### 5. Применение

- Только после подтверждения.
- Обновить `rawProjects`, фильтры, таблицу целей.
- Показать «Импортировано: X проектов, Y целей».
- Сохранить исходный файл и результат в историю (если task-003 уже есть).

### 6. Производительность и доступность

- Валидировать все строки, но показывать первые 100 в таблице.
- Не блокировать UI на файлах до 1000 строк.
- Модальное окно: фокус-ловушка, закрытие по Esc, `aria-*`.
- Светлая и тёмная темы, мобильный вид.

## Ограничения

- Без фреймворков и сборки.
- Не ломать существующий импорт и чат.
- Не отправлять в AI лишние персональные данные.
- Все строки экранировать.
- Код с комментариями на русском.

## Критерии приёмки

- [ ] Перед применением всегда показывается предпросмотр.
- [ ] Видно количество проектов и целей.
- [ ] Ошибки содержат строку, колонку, сообщение и пример.
- [ ] «Отмена» не меняет данные.
- [ ] Строки-продолжения обрабатываются.
- [ ] Дубли и некорректные даты/бюджеты видны.
- [ ] Можно скачать ошибки.
- [ ] После применения обновляются все блоки дашборда.
- [ ] Файл до 1000 строк не вешает интерфейс.
- [ ] Обе темы и мобильный вид корректны.

## Формат ответа

1. Список изменённых файлов.
2. Новый модуль `import.js` с полным кодом.
3. Патчи для `app.js`, HTML и CSS.
4. Пример `payload.json` с сырыми строками и результатом.
5. Чек-лист ручной проверки на 5 сценариях.
6. Ограничения и что делать с неоднозначными форматами.
