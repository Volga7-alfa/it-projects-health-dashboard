## User Story

> Я как руководитель, хочу смотреть дашборд с телефона, чтобы проверять статусы
> с планёрки или в дороге.
>
> Я как пользователь, хочу сохранять выбранные фильтры в ссылке, чтобы отправлять
> коллеге сразу нужный срез, а не просить настроить фильтры вручную.
>
> Я как аналитик, хочу сортировать и искать цели по названию, чтобы быстро находить
> нужную строку в большом портфеле.

## Зачем это нужно

Текущая вёрстка рассчитана на широкий экран: фильтры и таблица целей на телефоне
занимают много места, а ссылку на конкретный срез нельзя отправить. В результате
дашбордом пользуются только с ноутбука, а обсуждение статусов снова уходит в скриншоты.

## Область работ

### Входит

- Адаптивная шапка: компактные фильтры, кнопка «Фильтры» на узких экранах.
- Выдвижная панель фильтров на мобильном (drawer) с кнопками «Применить» и «Сбросить».
- Карточки проектов в одну колонку, читаемые отступы и размеры шрифта.
- Таблица целей:
  - горизонтальная прокрутка с тенью-подсказкой;
  - липкая шапка;
  - компактные колонки на мобильном;
  - альтернативный карточный вид для очень узких экранов (опционально).
- Поиск по названию цели.
- Сортировка таблицы по клику на заголовок: направление, проект, цель, статус, дата, просрочка.
- Синхронизация фильтров, поиска и сортировки с URL (`?direction=А&project=А1&q=...`).
- Кнопка «Скопировать ссылку на срез».
- Восстановление состояния из URL при открытии.
- Учёт safe-area на iPhone.
- Размер интерактивных элементов не меньше 44×44 px.

### Не входит

- Мобильное приложение.
- Полный редизайн десктопной версии.
- Офлайн-режим (PWA) — отдельная задача.
- Жесты swipe между карточками.
- Тёмная тема вручную (см. бэклог US-22).

## Брейкпоинты

| Ширина | Поведение |
|---|---|
| `≥ 1200px` | Текущая сетка, все фильтры в шапке |
| `768–1199px` | Карточки в 2 колонки, фильтры в одну строку |
| `< 768px` | Одна колонка, фильтры в drawer, таблица прокручивается |
| `< 480px` | Компактная шапка, крупные кнопки, минимальные отступы |

## Сценарии

1. **Телефон.** Пользователь открывает дашборд, видит заголовок, кнопку «Фильтры»
   и карточки в одну колонку. Нажимает «Фильтры», выбирает направление «А»,
   применяет — список обновляется, панель закрывается.
2. **Ссылка.** Пользователь копирует ссылку с фильтром «А» и проектом «А1»,
   отправляет коллеге. Коллега открывает — видит тот же срез.
3. **Поиск.** Пользователь вводит «цель 12» в поиск, таблица показывает только
   совпадающие строки.
4. **Сортировка.** Пользователь нажимает на «Просрочка», строки сортируются
   по убыванию, повторный клик — по возрастанию.
5. **Сброс.** Пользователь нажимает «Сбросить», URL очищается, возвращаются все данные.

## Критерии приёмки

- [ ] На ширине 360 px нет горизонтального скролла всей страницы.
- [ ] Фильтры на мобильном открываются в панели и не перекрывают контент навсегда.
- [ ] Таблица целей прокручивается внутри контейнера, шапка остаётся видимой.
- [ ] Поиск фильтрует строки без перезагрузки.
- [ ] Сортировка работает по всем основным колонкам и показывает направление сортировки.
- [ ] Фильтры, поиск и сортировка попадают в URL.
- [ ] При открытии ссылки состояние восстанавливается.
- [ ] Кнопка «Скопировать ссылку» показывает подтверждение.
- [ ] Кнопки и поля удобно нажимать пальцем (≥ 44 px).
- [ ] Десктопная версия не ухудшилась.
- [ ] Светлая и тёмная темы выглядят корректно.

## Технические заметки

- Использовать CSS `@media` и `clamp()` для типографики, без UI-фреймворков.
- Для drawer: `<dialog>` или блок с `aria-expanded`, фокус-ловушка, закрытие по Esc.
- URL:
  - `new URLSearchParams(location.search)`;
  - `history.replaceState(null, '', '?' + params.toString())`;
  - не писать `all` в URL, чтобы ссылки были короче.
- Состояние сортировки: `{ key, direction }`, переиспользовать в `renderGoalsTable`.
- Поиск — регистронезависимый, с `toLocaleLowerCase('ru')`.
- Не хранить в URL API-ключ и персональные данные.
- Для таблицы на мобильном можно скрыть второстепенные колонки и показать их
  в раскрывающейся строке.
- Пример мобильного макета — в [mockups/mobile-wireframe.md](mockups/mobile-wireframe.md).

## Риски и открытые вопросы

- На очень маленьких экранах таблица из 7 колонок остаётся неудобной — нужен ли
  карточный режим?
- Ссылка может стать длинной при большом количестве фильтров.
- Нужно ли сохранять сортировку в localStorage или только в URL?
- Как вести себя, если в URL указан несуществующий проект?
- Нужна ли отдельная мобильная навигация по разделам?
