## User Story

> Я как финансовый контролёр, хочу видеть платежи по проекту и их влияние на план/факт
> бюджета, чтобы замечать перерасход до закрытия проекта, а не после.

## Зачем это нужно

Сейчас в дашборде есть только два числа: `planBudget` и `factBudget`. Не видно, из чего
сложился факт, когда были платежи и какие из них ещё ожидаются. Из-за этого перерасход
обнаруживается поздно, а руководителю приходится сверяться с отдельной таблицей.

## Область работ

### Входит

- Модель платежа: проект, дата, сумма, назначение, статус, контрагент, комментарий.
- Список платежей в карточке проекта или отдельной вкладке «Финансы».
- Добавление, редактирование и отмена платежа.
- Статусы: `запланирован`, `оплачен`, `отменён`.
- Пересчёт `factBudget` по оплаченным платежам.
- Отображение перерасхода и оставшегося бюджета.
- История платежей с сортировкой по дате.
- Импорт платежей из Excel (после появления task-009).
- Экспорт реестра платежей в Excel.

### Не входит

- Проведение реальных платежей и интеграция с банком.
- Бухгалтерский учёт, налоги, счета-фактуры.
- Многовалютность (можно заложить поле `currency`, но UI — позже).
- Согласование платежей по ролям (зависит от task-001).

## Модель данных

```json
{
  "id": "pay-001",
  "project": "А1",
  "date": "2026-10-15",
  "amount": 250000,
  "currency": "RUB",
  "purpose": "Оплата подрядчику за этап 2",
  "status": "оплачен",
  "contractor": "ООО «Пример»",
  "comment": "Акт подписан"
}
```

## Сценарии

1. **Просмотр.** Пользователь открывает проект А1 и видит список платежей и итог по факту.
2. **Добавление.** Пользователь добавляет платёж на 250 000 ₽ со статусом «оплачен»;
   `factBudget` увеличивается на 250 000 ₽.
3. **Отмена.** Платёж переводится в «отменён»; факт уменьшается, история сохраняется.
4. **Перерасход.** Если сумма оплаченных платежей больше плана, карточка проекта
   получает красный статус и причину «перерасход X млн».
5. **Импорт.** Пользователь загружает Excel с платежами, видит предпросмотр и применяет.

## Критерии приёмки

- [ ] В карточке проекта виден план, факт, остаток и перерасход.
- [ ] Можно добавить платёж с датой, суммой, назначением и статусом.
- [ ] Можно редактировать и отменять платёж.
- [ ] `factBudget` пересчитывается только по статусу «оплачен».
- [ ] Отменённые платежи не влияют на факт, но остаются в истории.
- [ ] Суммы форматируются в рублях с разделителями тысяч.
- [ ] Данные сохраняются после перезагрузки (через task-003).
- [ ] Есть пустое состояние: «Платежей пока нет».
- [ ] Ошибки валидации: отрицательная сумма, пустой проект, дата в будущем
  для статуса «оплачен».

## Технические заметки

- Добавить в объект проекта массив `payments: []` или отдельный реестр `payments`,
  связанный с проектом по `project`.
- Не менять существующее поле `factBudget` в демо-данных: либо пересчитывать его
  из платежей, либо явно показывать, что оно ручное.
- Для дат использовать `YYYY-MM-DD`, для денег — целые числа в рублях.
- Форматирование: `new Intl.NumberFormat('ru-RU', { style:'currency', currency:'RUB', maximumFractionDigits:0 })`.
- Пример данных — в [payload.json](payload.json).
- UI: отдельная вкладка «Финансы» в модальном окне проекта или блок под карточкой.

## Риски и открытые вопросы

- Если `factBudget` уже заполняется из Excel, нужно решить: платежи заменяют его
  или дополняют? Иначе будет двойной учёт.
- Нужны ли плановые платежи по месяцам (cash flow) или достаточно реестра?
- Кто имеет право отменять платёж? Зависит от ролей в task-001.
- Нужна ли привязка к договору и счёту?
