# Промпт для ИИ — TASK-002 «Платежи и бюджет проекта»

> Приложи к промпту актуальные `app.js`, `data.js`, `styles.css`, `Дашборд_5.html`
> и `payload.json` из этой папки.

---

## Контекст

Проект — статический дашборд «Здоровье ИТ-проектов» на чистом HTML/CSS/JS.
В данных проекта уже есть `planBudget` и `factBudget` (в рублях), но нет детализации
платежей. Карточка проекта показывает план/факт в миллионах и подсвечивает перерасход.

## Задача

Добавить реестр платежей по проектам и связать его с бюджетом.

## Функциональные требования

1. **Модель платежа:**
   `id`, `project`, `date` (`YYYY-MM-DD`), `amount` (целое число рублей),
   `currency`, `purpose`, `status` (`запланирован` | `оплачен` | `отменён`),
   `contractor`, `comment`.
2. **UI:**
   - блок «Финансы» в карточке проекта или отдельная вкладка;
   - таблица платежей: дата, назначение, контрагент, сумма, статус, действия;
   - итоги: план, оплачено, остаток, перерасход.
3. **Действия:**
   - добавить платёж;
   - редактировать;
   - отменить (не удалять);
   - фильтровать по статусу.
4. **Пересчёт:**
   - `factBudget` = сумма платежей со статусом «оплачен»;
   - отменённые и запланированные не входят в факт;
   - если факт больше плана — красный бейдж и причина «перерасход X млн».
5. **Валидация:**
   - сумма > 0;
   - проект обязателен;
   - дата обязательна;
   - дата оплаченного платежа не позже сегодняшней;
   - понятные сообщения об ошибках.
6. **Форматирование:** рубли, разделители тысяч, без копеек.
7. **Сохранение:** использовать слой хранения из task-003, если он уже реализован;
   иначе — временно localStorage с пометкой TODO.
8. **Демо-данные:** добавить 3–5 платежей к проектам А1, А4 и Б2, включая перерасход.

## Ограничения

- Не добавляй фреймворки и сборку.
- Не ломай существующие карточки, фильтры и таблицу целей.
- Не делай реальных платёжных интеграций.
- Все пользовательские строки экранируй.
- Сохраняй стиль: стеклянные карточки, скругления, светлая/тёмная темы.

## Критерии приёмки

- [ ] В карточке проекта видны план, факт, остаток и перерасход.
- [ ] Платёж можно добавить, изменить и отменить.
- [ ] Факт пересчитывается корректно.
- [ ] Отменённый платёж остаётся в истории.
- [ ] Ошибки валидации понятны.
- [ ] Данные не теряются после перезагрузки.
- [ ] Мобильный вид и обе темы не сломаны.

## Формат ответа

1. Изменённые файлы и краткое описание изменений.
2. Новый код или патчи.
3. Обновлённый пример `payload.json`, если схема изменилась.
4. Чек-лист ручной проверки.
5. Открытые вопросы, которые нужно решить до продакшена.
